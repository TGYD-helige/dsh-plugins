# dsh-telemetry backend research

Research date: 2026-11-06. Scope: [Issue #109](https://github.com/TGYD-helige/dsh-plugins/issues/109), tracing only. This is a source review, not a declaration of tested backend compatibility.

## Transport and configuration

- **Phoenix:** the owning [trace router](https://github.com/Arize-ai/phoenix/blob/main/src/phoenix/server/api/routers/v1/traces.py#L431) only accepts `application/x-protobuf` (HTTP JSON returns 415). Use `@opentelemetry/exporter-trace-otlp-proto` for both backends. Use OTLP/HTTP protobuf at `<Phoenix application base>/v1/traces` (local default `http://localhost:6006/v1/traces`). Preserve deployment prefixes, including Cloud space paths; append the suffix only once. The official TS normalizer preserves existing paths. Use the deployment's Settings hostname rather than constructing a Cloud hostname. [Endpoint normalization](https://arize-ai.github.io/phoenix/functions/_arizeai_phoenix-otel.register.ensureCollectorEndpoint.html), [Phoenix SDK configuration](https://github.com/Arize-ai/phoenix/blob/main/packages/phoenix-otel/README.md).
- Phoenix authentication is optional for unauthenticated self-hosting; otherwise send `Authorization: Bearer <PHOENIX_API_KEY>`. Phoenix authentication defaults off. Do not confuse Phoenix keys with Arize AX's `api_key`/`space_id` headers. [Authentication](https://arize.com/docs/phoenix/self-hosting/features/authentication).
- Phoenix uses resource attribute `openinference.project.name`. Relevant environment inputs are `PHOENIX_COLLECTOR_ENDPOINT`, `PHOENIX_API_KEY`, and project name. Current TS docs prefer `PHOENIX_PROJECT`, then `PHOENIX_PROJECT_NAME`, then `default`; Python docs commonly use `PHOENIX_PROJECT_NAME`. These are SDK conveniences: a bare OTel exporter does not automatically resolve Phoenix variables. Resolve them explicitly in the adapter. [TS parameters](https://arize-ai.github.io/phoenix/types/_arizeai_phoenix-otel.register.RegisterParams.html), [pinned TS implementation](https://github.com/Arize-ai/phoenix/blob/9212a42a512d08de7e2a8e81b15821f4483812ce/js/packages/phoenix-otel/src/register.ts).
- **Langfuse:** trace exporter URL is `<base>/api/public/otel/v1/traces`; Basic auth encodes `publicKey:secretKey`. Both HTTP/protobuf and HTTP/JSON work; gRPC does not. Native OTLP requires self-hosted Langfuse >=3.22.0. Current v4 docs request `x-langfuse-ingestion-version: 4` for real-time ingestion; this does not establish older-server compatibility. Propagate user/session/name/tags/version/release/trace metadata to every span because filtering increasingly uses observations. Prefer direct attribute stamping over process-global baggage changes. [Native OTLP](https://langfuse.com/integrations/native/opentelemetry).
- Langfuse environment maps to `langfuse.environment`; `LANGFUSE_TRACING_ENVIRONMENT` is its documented SDK variable, default `default`. Names must match `^(?!langfuse)[a-z0-9-_]+$`, maximum 40 characters. For Phoenix, carry a generic `deployment.environment.name` resource attribute and/or metadata; this research does not establish an equivalent first-class Phoenix environment selector. [Langfuse environments](https://langfuse.com/docs/observability/features/environments).

## Practical mapping

Recommendation: preserve IDs, parent context, timestamps, OTel status and lifecycle in one collector. Adapters return attributes/resource/exporter settings only; use one isolated provider and one shared batch/export/flush/shutdown path. Phoenix's convenience `register` defaults to global registration, so directly constructing the isolated provider is safer for this issue. [Pinned Phoenix implementation](https://github.com/Arize-ai/phoenix/blob/9212a42a512d08de7e2a8e81b15821f4483812ce/js/packages/phoenix-otel/src/register.ts).

| Unified field | Phoenix/OpenInference | Langfuse |
| --- | --- | --- |
| Turn/subagent/task | `openinference.span.kind=AGENT` | `langfuse.observation.type=agent` where tested; legacy-compatible `span` otherwise |
| LLM call | kind `LLM`; `llm.system`, `llm.model_name` | type `generation`; `langfuse.observation.model.name` |
| Tool | kind `TOOL`; tool name/parameters | type `tool` |
| Hook/request detail | kind `CHAIN`; descriptive span name | type `span` |
| IO | JSON strings `input.value`/`output.value`, MIME `application/json` | JSON strings `langfuse.observation.input`/`output` |
| Model parameters | JSON `llm.invocation_parameters` | JSON `langfuse.observation.model.parameters` |
| Usage | integers `llm.token_count.prompt`, `.completion`, `.total`; detailed cache/reasoning keys | JSON `langfuse.observation.usage_details` |
| Context | `session.id`, `user.id`, `tag.tags`, JSON `metadata` | `session.id`, `user.id`, `langfuse.trace.tags`, trace/observation metadata |

Phoenix types and core IO/context conventions come from the [OpenInference semantic conventions](https://github.com/Arize-ai/openinference/blob/main/spec/semantic_conventions.md). Langfuse's exact serialization and attribute names are implemented in its [official attribute builder](https://github.com/langfuse/langfuse-python/blob/main/langfuse/_client/attributes.py). The table's operation assignments are proposed dsh mappings, not server-tested rendering claims.

For Phoenix, emit flattened indexed attributes, e.g. `llm.input_messages.0.message.role` and `llm.output_messages.0.message.tool_calls.0.tool_call.function.name`. Preserve call IDs, JSON arguments and tool-result linkage. Reasoning content can occupy ordered `message.contents` entries. Prompt totals must include cache tokens when the provider excludes them; completion totals already including reasoning must not have reasoning added again. [LLM span spec](https://github.com/Arize-ai/openinference/blob/main/spec/llm_spans.md), [token conventions](https://github.com/Arize-ai/openinference/blob/main/spec/semantic_conventions.md).

The existing `packages/dsh-langfuse/src/client.ts#usageOf` already partitions cache and reasoning buckets for Langfuse; reuse that accounting without applying its disjoint-bucket rules to Phoenix's inclusive totals. Preserve the existing collector's reasoning/message output shape until real Langfuse UI readback establishes equivalence.

## Media and privacy

Langfuse SDK media extraction is additional behavior beyond OTLP export: extract data URIs, upload to object storage, replace payloads with references. Current docs describe server-side base64 fallback, but give no minimum server version for that fallback. External URLs render directly; self-hosted managed media needs configured object storage. Direct media upload uses a separate media API, so parity cannot be assumed merely from replacing `LangfuseSpanProcessor` with an OTLP exporter. Validate bounded data-URI rendering on the actual target; otherwise explicitly document metadata-only degradation rather than silently dropping it. [Langfuse multimodality](https://langfuse.com/docs/observability/features/multi-modality).

Phoenix image convention is flattened `...message.contents.<n>.message_content.image.image.url`, accepting external/data URLs. Newer conventions also include non-LLM `input.images`/`output.images`, audio/video and reasoning parts; specification presence does not prove historical UI rendering. OpenInference's current shared masking does not cover all audio/video cases, so enforce dsh capture policy independently. [Multimodal spec](https://github.com/Arize-ai/openinference/blob/main/spec/multimodal_attributes.md).

Recommendation: reuse bounded attachment reads and cancellation in `packages/dsh-langfuse/src/media.ts`; apply capture/redaction/credential/payload safeguards again after adapter mapping so indexed message fields cannot leak content when `captureContent=false`. Never place backend auth in span attributes or logged exporter configuration.

## Readback and compatibility gates

- Phoenix's `getSpans` supports project/time/trace filters and returns span details; `getTraces({includeSpans:true})` requires server >=13.15.0. REST project trace listing is `GET /v1/projects/{project_identifier}/traces`; span listing is the corresponding `/spans` route. Paginate and assert physical IDs/parents, times, kinds, model, usage and IO. [Client API](https://arize-ai.github.io/phoenix/modules/_arizeai_phoenix-client.html), [getTraces version requirement](https://arize-ai.github.io/phoenix/functions/_arizeai_phoenix-client.traces_getTraces.getTraces.html), [release notes](https://arize.com/docs/phoenix/release-notes).
- Langfuse Cloud/v4 readback uses `GET /api/public/v2/observations`, bounded by time and trace ID, requesting IO/model/usage field groups; group observation rows by trace ID. Self-hosted v3 uses `GET /api/public/observations` instead. Poll with a deadline: export/flush completion is not read visibility. [Public API](https://github.com/langfuse/langfuse-docs/blob/main/content/docs/api-and-data-platform/features/public-api.mdx), [official client read semantics](https://python.reference.langfuse.com/langfuse).
- Before claiming support, pin and record dsh, OTel API/SDK/exporter, backend server/image versions, and the convention/source revision used. Exercise both backends with real dsh/LLM plus UI/API reads covering roots, tools, hooks, subagents, A2A, reasoning and media. Current documentation and unversioned `main` sources remain evidence of intended behavior only. No backend or live LLM was contacted for this research.
